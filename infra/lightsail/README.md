# Phase 1 Lightsail infrastructure

This root implements the administrator's [Phase 1 decision](../../docs/decisions/aws-initial-budget.md). It creates one Linux Lightsail instance, a static IPv4 address, a firewall open only for HTTPS/HTTP and operator-restricted SSH, a private Lightsail object-storage bucket attached to that instance, and an account-wide US$50/month AWS Budget with 80%-actual and 100%-forecast alerts. It does **not** run `terraform apply` from CI or create ECS/RDS/ALB.

Before planning, confirm the active **4 GiB public-IPv4** bundle and Linux blueprint in the chosen Region with `aws lightsail get-bundles` and `aws lightsail get-blueprints`. The [AWS plan table](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-bundles.html) lists the standard 4 GiB IPv4 instance at US$24/month; prices and bundle IDs can change. Confirm a private bucket bundle with `aws lightsail get-bucket-bundles` and include its price in the R$200 total. The US$50 budget **alerts**; it does not stop spending and is not the same as the R$200 cap after exchange-rate changes.

1. Have an AWS account/Region, restricted operator CIDR, Lightsail key pair, notification email, and public domain ready. Do not put credentials in `terraform.tfvars` or Git.
2. Use the existing [backend bootstrap](../terraform/bootstrap/) to create protected remote state, then initialize this root with `terraform init -backend-config="bucket=..." -backend-config="region=..."`. Protect the bootstrap state until it has been migrated. Do not use local state for a live apply.
3. Copy `terraform.tfvars.example` to an ignored `terraform.tfvars`, replace every placeholder, run `terraform plan`, review the complete cost and resource actions, and only then apply using an approved AWS identity. The instance and bucket have `prevent_destroy`; backups are never auto-deleted by Terraform.
4. Point the domain's A record to the `public_ip` output. Install Docker Engine, Compose, Python 3.12, PostgreSQL 16 client tools and AWS CLI on the host, and follow [the Phase 1 deployment runbook](../../docs/runbooks/lightsail-phase1.md). Check that the fixed Compose network `172.30.84.0/24` does not overlap a host/VPN network.
5. Verify the instance can access its private bucket from both the host AWS CLI and the API container **without access keys**. Lightsail [resource access](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-configuring-bucket-resource-access.html) is the intended path. If the container cannot obtain the attached credentials, stop the rollout and fix that access path; do not commit keys or create a Terraform-managed access key, which would put the secret in state.

The Terraform root has no SSH bootstrap or automatic deploy: software installation, migrations, secret injection, restore tests and go-live evidence remain explicit operator steps. Existing ECS/RDS Terraform is reserved for the later phase.
